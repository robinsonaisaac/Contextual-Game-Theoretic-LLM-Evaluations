# Game-Mechanics Audit — Five Play Engines + Shared Infrastructure

- Date: 2026-07-21.
- Method: six parallel read-only audit agents (one per engine — ONW, Secret Hitler, Diplomacy-lite, Monopoly-lite, Risk-lite — plus one for shared infra: `runner.py`/`messaging.py`/`alliances.py`/`metrics.py`/`viewer.py`) evaluated four dimensions — rules fidelity, hidden-information integrity, metric correctness, test coverage — each finding backed by direct code execution, not inspection alone. This was followed by six independent adversarial verification agents instructed to refute every finding; only findings that survived adversarial verification (CONFIRMED, or CONFIRMED-with-reassessed-impact) appear below, and the verified files' verdicts/`affects_reported_numbers` judgments override the original audit where they differ. Empirical reproduction against real production logs (`data/runs/{dip,mono,risk,game,sh}_steering_v1{,_v2}/`) is noted per finding where a verifier did it.

## Findings affecting reported numbers — THE KEY SECTION

### Paper (ONW + Secret Hitler results)

- **ONW night-action broadcast leak (Critical, CONFIRMED).** `game_theory_llm/play/games/one_night_werewolf.py:798-811`, with delivery via `players/llm.py:87-90` and `players/steered_llm.py:94-95`, `runner.py:190-201`. `observations()` scopes only `wolf_acknowledge, wolf_peek_center, minion_acknowledge, mason_acknowledge, seer_peek_player, seer_peek_center, robber_swap, insomniac_check, doppel_copy` to the acting seat; every other night action (`tm_swap`, `drunk_swap`, `seer_pass`, `robber_pass`, `tm_pass`, `wolf_no_peek`) falls through to a full broadcast `Obs(audience=list(range(n_players)), ...)`. This reaches every seat's live prompt via both `LLMPlayer` and the steering-results `SteeredLLMPlayer` (confirmed both classes render it into history) — not merely a post-hoc log artifact. Troublemaker/Seer/Robber appear in every 3–10p deck and both leak; Drunk (8–10p) leaks every turn. **Published number affected:** the judge cooperation/aggression ratings and pro-social (village) win rate computed over ONW transcripts, because the leaked role/swap info persists in bystander history through DAY and VOTE — contaminating the very transcripts the judge rates. Direction/magnitude: systematic, unquantified magnitude (mechanism-level, not yet isolated to a Δ).

- **Secret Hitler sequential open ballot (Important, CONFIRMED).** `secret_hitler.py:1020-1023` (broadcast fallthrough) + `secret_hitler.py:277-281` (`active_player` in `PH_VOTING` returns first not-yet-voted living seat) + `runner.py:190-201` (per-Obs delivery) + `players/llm.py:87-90`. `vote` is not in the private-reveal branches, so each `ja/nein` is broadcast to all seats immediately, and the runner delivers it before the next voter acts — reproduced: seat k sees every living seat `<k`'s vote before casting its own, turning the documented "simultaneous secret ballot"/"full official game" into a sequential public ballot in ascending seat order. **Published number affected:** Liberal-side win rate and the judge cooperation/aggression transcript ratings for Secret Hitler, since these are measured on a sequential-open-ballot variant, not the documented simultaneous-secret-ballot game; RandomPlayer ignores observations so only the measured LLM runs are affected. Direction/magnitude: systematic advantage to later voters, unquantified magnitude. (Does not affect the 7.7% SH parse-fallback rate, which is parsing-side and independent of vote timing.)

- **Whisper double-count → public-message-ratio bias (Critical, CONFIRMED, root cause shared).** Root cause: `messaging.py:249-250` (`nego_observations` builds a bystander `Obs` whose `log=dict(full)` is tagged `type: "message"`, indistinguishable from the true recipients' record) + `runner.py:79-80,191` (each `Obs` gets a fresh, never-repeating `event_id`). Consumed by `metrics.py:73` (`load_match`'s dedup key `(event_id,)` can never collapse the two records) and, for the actual published numbers, by the sibling reimplementation `scripts/analyze_game_steering.py`'s `objective_metrics()` (iterates raw `observation` records with `obs.type=="message"`, no dedupe at all) and `build_transcript()` (prints a transcript line for every such record, i.e. duplicates every whisper's line verbatim in the text sent to the Claude-Sonnet-4.6 judge). **Published numbers affected, quantified against real production logs backing `docs/results/steering_in_games_report.md`:** ONW baseline — buggy pooled `public_msg_ratio` 0.867 vs true 0.929 (~7% relative downward bias); `msgs_per_match` inflated 495→true 462 (~7%). Secret Hitler baseline — buggy pooled `public_msg_ratio` 0.364 vs true 0.531 (**17-point / ~46% relative** downward distortion); `msgs_per_match` reported 95.68/match vs true 65.48/match (~46% inflation). Within the judge's truncated 9000-char transcript window for a real SH match, whisper lines occupy ~49% of characters vs. an expected ~24-25% share — roughly 2x overrepresentation, at the direct expense of showing the judge more of the game's actual turns/outcome. Distortion always runs the same direction (inflates private/whisper volume, deflates public ratio) and scales with whisper-heavy games (SH >> ONW). Win-rate and alliance-summary numbers are unaffected (read `terminal.winner`/`terminal.alliance_summary`, untouched by this bug).

### Steering report (five-game replication)

- **Diplomacy fallback pool structurally excludes SUPPORT/CONVOY (Critical, CONFIRMED).** `diplomacy_lite.py:632-654` (`_movement_legal_actions`), `:668-683` (`_winter_legal_actions`, always proposes Army over Fleet even on coastal home centers). `runner.py:157` draws the parse-failure fallback from exactly this curated pool (HOLD/MOVE/BUILD-Army only). **Published number affected:** `docs/results/steering_in_games_report.md`'s Diplomacy "competence floor / no directional bias" framing and the stated 30-67% fallback rate. Verifier re-derived from the real `dip_steering_v1` production logs (100 matches): of 5,828 order-instances, 147 (2.5%) are genuine LLM-parsed SUPPORT orders and 0 are CONVOY, and every one of the 147 SUPPORT orders came from a successful parse — none from fallback (fallback is 100% {HOLD, MOVE, BUILD, DISBAND}). Scoping "fallback rate" to actual order-submission turns only (excluding negotiation messages) gives a **true fallback rate of 94.6%** (1,749/1,848 `submit_orders` turns), far higher than the report's stated 30-67% (diluted by counting negotiation messages in the denominator). Direction: SUPPORT (the primary cooperative-signal vehicle) is structurally impossible under fallback, and ~95% of order content in the Diplomacy transcripts is fallback-derived, not LLM-authored — this reinforces the report's own "competence-floor/uninterpretable" verdict but means the true noise floor is considerably worse than disclosed, and the "no bias" claim is factually false.

- **Monopoly α=-4 condition parse-error/fallback confound (Important, CONFIRMED, undisclosed).** Verifier computed parse-error and fallback rates per condition directly from the real `mono_steering_v2` sweep data (25 seeds/condition, matches `aggregate.json` exactly): baseline 1.9% fallback / 7.5% parse-error; **coop_a-4 (the headline result) 16.9% fallback / 58.8% parse-error**; coop_a+2 0.3%/1.9%; coop_a+4 0.5%/3.4%. **Published number affected:** the report's caveat ("Parse errors ~7%, fallback ~2%: well within the measurable regime," line 233) reproduces only the baseline condition's rate — it does not disclose that the α=-4 condition, which delivers "the strongest single contrast in the entire 5-game study" (Δ+19.2 aggression, p=4.2e-06), has an 8-9x higher parse-error/fallback rate than what the report states. Nearly 1 in 6 of all decisions at α=-4 are uniform-random fallback actions, and over half of raw model outputs fail to parse on first attempt — a genuine, directly-measurable confound on the strongest claimed effect that plausibly explains at least part of the "aggression" signal as format-compliance collapse under strong negative steering rather than (or in addition to) coherent adversarial dialogue.

- **Secret Hitler alliance vote-time judging distorts betrayal/honour rates (Important, CONFIRMED).** `secret_hitler.py:900-937` (`_judge_vote_pacts`), kind filter at line 912, contradicting the module docstring (28-31) which assigns vote-time judging to `vote_pact` only and enact-time judging to `gov_pact`. Code judges `vote_pact`, `gov_pact`, AND `nonaggression` at every vote. Verifier reproduced: a `nonaggression` pact whose members vote differently (routine) is flagged betrayed even though nonaggression says nothing about voting; a `gov_pact` is judged BOTH at vote time (betrayed on vote misalignment) AND at enact time (honored when the promised policy is enacted) — because the reducer makes betrayal dominate (`alliances.py:451`), the alliance's terminal bucket becomes `n_betrayed` even though the promised policy was later enacted, and `first_betrayal_turn` is pulled earlier. **Published number affected:** alliance `betrayal_rate`/`honour_rate`/`first_betrayal_turn` in the Secret Hitler steering rows — inflated toward betrayal whenever gov_pact/nonaggression alliances form and members ever vote apart (made more likely by the sequential-open-ballot finding above). Adversarial caveat: vote-time judging of all three kinds is partly intended by the method's own docstring/tests, so it is not a stray bug — but the gov_pact double-judge + betrayal-dominance flip is asserted by no test and contradicts the module's own stated design.

- **Risk alliance-ledger leak + private-message double-count in published `risk_steering_v1` logs (both Critical, CONFIRMED).** (1) `risk_lite.py:310-333` (`_public_header`, esp. 317-321) lists every `status=="active"` alliance unfiltered by requesting player, spliced into every seat's `render_prompt` unconditionally in every phase — contrasted with `diplomacy_lite.py:752-758` and `monopoly_lite.py:782-785`, which correctly filter with `player in al.members`. Verifier found this **already fired in the actual published dataset**: `data/runs/risk_steering_v1/coop_a+2/seed20.jsonl` has one alliance (`#1 {P0,P1}`) reach active, and P2 (a non-member) was shown "Active alliances: #1 {P0,P1} coalition" in 41 of its own subsequent prompts. Does not meaningfully move the aggregate headline judge indices because alliance formation is independently near-zero across the published run (matching the report's own disclosed "near-zero" alliance limitation), but is load-bearing for any qualitative diplomatic-behavior claim and would become directly consequential once that affordance gap is fixed. (2) Same whisper double-count root cause as the ONW/SH finding above (`messaging.py:249-250`/`runner.py:191`), independently reimplemented in `scripts/analyze_game_steering.py`'s `objective_metrics()`. Verifier cross-checked against real ground truth in `data/runs/risk_steering_v1/coop_a-4/seed0.jsonl`: 4 `say` + 5 `whisper` actions (9 true messages) vs. reported `pub=4, priv=10` (private exactly doubled). **Published number affected:** `data/runs/risk_steering_v1/results/aggregate.json`'s "public-message ratio" — recomputed with proper whisper-dedup vs. as-published: baseline 0.86 (published) vs ≈0.90-0.91 (corrected); coop_a-4 0.53 (published) vs ≈0.66 (corrected) — a **4-16 percentage-point understatement** of public-message ratio in every condition. Cross-condition monotonic ordering happens to survive in this dataset, but the absolute published numbers are measurably wrong.

- **Monopoly trade actions in published logs all originate from fallback, never model decisions (Critical code defect; impact REASSESSED downward, CONFIRMED).** `monopoly_lite.py:852-867` (`parse_action`'s `PH_ROLL` branch is hard-coded `{"type":"roll"}`, ignoring model text unconditionally) + `messaging.py`'s `nego_parse` (no `propose_trade` tag exists in the negotiation grammar). The documented "cooperation surface" (module docstring lines 45-51: trades surfaced "so LLM players can see and choose them") is unreachable by both real LLM player classes; only `RandomPlayer`/parse-failure fallback can emit `propose_trade`. Verifier grepped the real production log `coop_a-4/seed0.jsonl`: **every single `propose_trade` action in that match is immediately preceded by a fallback record** — i.e., empirically, 100% of trade proposals came from parse-failure random fallback, not coherent LLM intent. **Verifier explicitly reassessed impact downward:** `build_transcript()` in `scripts/analyze_game_steering.py` — the exact code producing the published means — only emits `message` (say/whisper), `alliance_event`, `vote`, and the terminal winner line; it **never includes `propose_trade`/`accept_trade`/`buy`/`decline` actions or `state.history` at all**, functioning or not. So there is **no direct path from parser bugs into the judge indices** because `build_transcript()` omits buy/decline/trade actions structurally. The bug does falsify the report's narrative framing of Monopoly as "the most economically explicit cooperation setting" and its claim that "trade willingness" is a measured cross-game behavioral axis (report lines 207-208, 247) — that mechanic essentially never executes for a real LLM decision — but it does not corrupt the literal headline judge numbers (cooperation/trust/aggression indices, which the verifier confirmed match `aggregate.json` to 2 decimal places via 51.64/46.32/28.04).

## All other confirmed findings

**onw**
- Important — `one_night_werewolf.py:904-909` (`_resolve`): a full vote tie (max multiplicity 1) eliminates ALL voted-for seats instead of "no one dies," flipping a canonical werewolves win into a village win; reproduced exact scenario.
- Important — `one_night_werewolf.py:858-859` vs docstring 842-844: `judge_alliance` judges `broken` alliances too (not just `active`), double-counting a defection as both `break` and `betrayed`/`honored`.
- Minor — `one_night_werewolf.py:809-811` + `runner.py:180-203`: votes are revealed sequentially (each seat's vote broadcast before the next votes) rather than simultaneously; undocumented.
- Minor — `one_night_werewolf.py:665-677`: Minion no-wolf-in-play prompt text says it wins "if no player is killed," but `_winner`/`rewards` never award werewolves the win in that branch — misleading prompt, no behavior change.

**secret_hitler**
- Minor — `secret_hitler.py:807`: election tracker reset to 0 on any passed vote (before enactment); redundant on the normal path, but on the veto-agree path with pre-election tracker=2 it advances only to 1 instead of triggering chaos at 3. Reproduced.
- Minor (downgraded from Important) — no test positively drives the two special win conditions (Hitler-elected fascist win, kill-Hitler liberal win); both verified correct by direct positive drive.
- Minor (downgraded from Important) — the uniform parse-fallback claim is correct but untested; reproduced 0.4993 ja over 10k draws.
- Minor — no test for chaos/tracker auto-enact, term-limit `n_alive>5` eligibility rule, normal presidency rotation, or special-election `resume_president` restore.

**diplomacy_lite**
- Critical — `diplomacy_lite.py:1447-1452` (`observations()`, `submit_retreats`/`submit_builds` branch): retreat/build-phase orders broadcast to every living power as soon as each power submits, before others in the same simultaneous phase have acted — the exact "B5" bug class fixed for movement but never extended to retreat/build. Downgraded to Important on verification: neither `LLMPlayer._format_obs` nor `SteeredLLMPlayer.receive_observation` has a handler for the `"resolution"` obs type, so it reaches the JSONL god-log but never a seat's actual prompt; fired live for builds (19/149 `submit_builds` had non-empty leaked content) but retreats never occurred in the production dataset (0 across 100 matches).
- Critical — `diplomacy_lite.py:180-201`/`:930-947`: convoy destinations are never checked for occupiability by unit type; an army can be convoyed onto a sea province and is then permanently stranded there (`ADJ_ARMY[sea]` always empty). Reproduced end-to-end (`A LON - SKA VIA CONVOY`). Dormant in the published dataset: 0 `via_convoy`/CONVOY orders anywhere in 100 production log files.
- Important — `diplomacy_lite.py:1320-1348` (`_judge_movement`): support_pact "omission betrayal" fires regardless of geographic feasibility (units may be unable to support at all), spuriously flagging betrayal. Reproduced with a France/Russia pact with disjoint neighbour sets. Dormant: 0 `alliance_accept` actions in the published dataset, so no alliance ever reached "active."
- Important — `diplomacy_lite.py:597-603`/`:991-1001`/`:1162-1176`: multi-unit retreat contention resolves by seat-processing order (lower-index power wins a shared retreat province) rather than a symmetric "both disband" clash; undocumented beyond the single-unit case. Reproduced (Austria claims EDI over England). Never fired: 0 retreat phases in the published dataset.
- Important — `alliances.py:301-305` (`alliance_observations`, `alliance_break` branch): breaking an alliance broadcasts its `kind` and full `members` list to every living player, not just members/counterparties — the sole branch broadcast table-wide (propose/accept/decline correctly scope to members∪pending). Verifier confirmed this DOES reach real players' decision context (both player classes have an `alliance_event` handler), unlike the retreat/build leak — but 0 `break` events occurred in the published dataset.

**monopoly_lite**
- Important — `monopoly_lite.py:858-862`/`:863-866`: naive substring matching in `parse_action` misclassifies negated statements (e.g., "I do not want to buy" → `{"type":"buy"}`; "I will not accept this trade" → `{"type":"accept_trade"}`), silently executing the opposite of a model's stated decision. Confirmed live in production data (buy/decline/accept_trade actions with `prev_type=prompt`, i.e., normally parsed, not fallback — 6 buys/8 declines/6 accepts/1 reject in one match alone). No direct judge-index path (same `build_transcript()` omission as the trade finding above), but a real, unquantified second-order channel remains via corrupted cash/property state feeding each player's own next prompt.
- Important — `monopoly_lite.py:457-461`/`:704-719`/`:722-765`: proposing a trade during the negotiation phase silently truncates that round for every other player (their remaining speak-queue slots are lost, `NegotiationState` left stale) and contradicts the docstring's "roll phase only" framing. Confirmed to directly suppress already-published aggregate columns (`msgs_per_match`, `public_msg_ratio`, `n_proposed`/`formation_rate` — all present in `aggregate.json`) for every player queued behind the proposer — the most directly consequential of the Monopoly findings on published numbers. Verifier additionally found a related unclaimed bug: `propose_trade` attributes the trade to `state.player_names[state.current_player_idx]` rather than the seat that actually acted.
- Important — `monopoly_lite.py:590-595` (`_advance_turn`): turn-cap net-worth ties are broken deterministically toward the earlier-indexed seat (Python `max()` first-argmax), undocumented, no randomization. Reassessed as not affecting this report specifically: Monopoly steering is an all-seats-steered design with no per-seat/per-model win-rate table this could skew, and `coop_side_win` is a dead column for Monopoly (game absent from `COOP_SIDE` dict) — remains a real bug and a live hazard for any future per-seat win-rate analysis.
- Important — `monopoly_lite.py:771-827` (`render_prompt`, 6-line history cap): the only channel conveying property ownership to other seats is a shared, global 6-line history window that can evict a purchase event before an opponent's prompt refreshes, despite the docstring's "mostly open-information" framing; the generic `observations()` broadcast for roll/buy/decline carries no compensating square/property detail. Assessed as the most plausible of the hidden-info findings to reach the judge indirectly, since it acts upstream of the free-text say/whisper content `build_transcript()` does read — magnitude unquantified.

**risk_lite**
- Important — `risk_lite.py:265-278` vs `:439-458`: `legal_actions()` for `PH_FORTIFY` enumerates only the maximal-count move per (src,dst) pair, while `parse_action` accepts any count in `1..armies-1` — the fallback/`RandomPlayer` sampling is uniform, but the underlying legal-set it draws from is truncated, biasing toward "move everything." Verifier confirmed `_fortify_prompt` does not show the LLM a `legal_actions()`-derived list at all (unlike `_attack_prompt`), so normal LLM-driven fortify decisions are not biased by this — it only bites `RandomPlayer` baselines and the rare parse-failure fallback. No fortify-count metric reported anywhere in the steering report.
- Important — `risk_lite.py:41,101,684-731`, `alliances.py:120-128` (`is_allied`): the four documented alliance "kinds" (nonaggression/mutual_defense/dmz/coalition) are mechanically identical — `kind` is stored/displayed but never consulted by any enforcement/legality/betrayal logic. No alliance-kind breakdown is reported anywhere.
- Important — `risk_lite.py:228-231` (`_award_card`): card-type assignment is deterministic (cyclic by hand size mod 3), guaranteeing every player a complete tradeable set by their 3rd card, every time — eliminates Risk's card-luck economy; disclosed in an inline code comment ("so smoke runs stay stable") but not in the class docstring. No card-economy metric is reported.
- Minor — `risk_lite.py:212-226`/`652-655`: card trading is fully automatic (auto-cash any held set at start of every turn, beyond the documented forced-trade-at-5 rule) — no player-facing trade action exists at all.
- Minor — `alliances.py:159-202` vs `:274-307`: negotiated alliance "terms" text is captured on the `Alliance` object but never included in any observation delivered to the invitee — the opposite-direction gap (under-informed party, not over-informed bystander).

**shared infra**
- Critical (impact class explicitly noted as replay-tool-only) — `messaging.py:249-250` → `runner.py:191` → `viewer.py:215-226,298-334`: the offline replay tool (`viewer.py --seat N`, `--html` export) shows a bystander seat the full text of a private whisper between two other seats, because the god-log `Obs.log` channel is type-tagged identically (`"message"`) to a genuinely delivered message and the viewer's masking filter only inspects that type tag. Verified this does NOT reach any live per-turn prompt: `runner.py:199-201` delivers only `o.payload` (correctly masked `message_meta`) to `receive_observation`, and `render_message_log` reads only `state.nego.transcript` with its own independent audience check. No analysis/report script in the repo invokes `--seat` (grepped `scripts/`+`docs/`); the report's own "Reproduce" section only calls `--god`. Caveat: the spec doc brands `--seat N` as "the visual QA that masking is correct," so any manual QC pass or case-study excerpt built from it would be silently corrupted — a real but not-yet-realized risk.

## Downgraded/refuted

1. **Secret Hitler — uniform parse-fallback (F4 in original SH audit): Important → Minor.** Correctness itself verified clean (uniform `rng.choice` over the legal set, 10k-draw reproduction at 0.4993 ja); downgraded because it is a pure coverage gap on already-correct code, not a live defect.
2. **Secret Hitler — special win-condition tests (F5): Important → Minor.** Both win paths (Hitler-elected fascist win, kill-Hitler liberal win) verified correct by direct positive drive; downgraded for the same reason — coverage gap on verified-correct code.
3. **Diplomacy retreat/build mid-phase leak (F2): Critical → Important.** Real and reproduced at the JSONL/god-log level, but neither real player class (`LLMPlayer`, `SteeredLLMPlayer`) has a handler for the `"resolution"` obs type, so the leak never reaches a seat's actual prompt/decision text — a materially less severe situation than the pre-fix "B5" bug it resembles, which used a rendered `"action"`-typed payload.
4. **Monopoly — missing `parse_action` test coverage (F6): Critical → Important.** Confirmed zero coverage of the only path real LLM players use, but relabeled for internal consistency with Findings 7/8 (also test-coverage absences rated Minor) — a missing test is a process gap, not itself a runtime defect, even though this specific gap enabled two Critical live bugs to ship.

## Test-coverage gaps

- **Universal gap: no test anywhere in the repository exercises the parse-fallback uniformity claim** for any of the five games. `grep -rn "fallback" tests/` turns up only unrelated hits (`test_extract_last_number_fallback` in `test_capability_scoring.py`, an unrelated viewer board-art fallback string) — `runner.py:151-159`'s `rng.choice(legal)` path, the single mechanism underpinning the paper's "unbiased random legal moves" claim across all five games, has zero regression protection anywhere.
- ONW: no test masks the exact leak in Finding 1 (`tm_swap`/`drunk_swap`/`*_pass`/`wolf_no_peek` bystander scoping); no test for vote full-tie, no-werewolf/`nobody` outcome, Doppelganger-Hunter drag, Robber/Troublemaker win effects, or broken-alliance judging.
- Secret Hitler: no test for chaos/tracker auto-enact, term-limit eligibility (`n_alive>5` rule), normal presidency rotation, or special-election `resume_president`.
- Diplomacy: none of its 7 confirmed findings has a covering test (fallback-pool representativeness, retreat/build mid-phase leak, convoy-to-sea, message double-count, omission-betrayal feasibility, retreat contention, alliance-break audience); win attribution (solo victory, last-power-standing, cap tie-break) has only indirect coverage.
- Monopoly: `parse_action` (the only path real LLM players use) has zero coverage in `test_monopoly.py`, directly enabling the buy/trade-negation and unreachable-trade findings; the runner fallback-uniformity property is untested; the turn-cap tie-break test explicitly skips its own assertion on a tie (`if worths.count(max(worths)) == 1:`).
- Risk: no test renders `render_prompt`/`_public_header` to check non-party alliance leakage (the precise gap that let the Risk alliance-ledger finding ship — contrast ONW's `test_onw.py:154`, which does assert `secret not in render_prompt(...)` for bystanders, showing the pattern exists elsewhere but was never applied to Risk); `test_metrics.py` has zero tests of the message-tally block (`total`/`public`/`private`/`meta`/`private_ratio`) that the double-count bug corrupts; the round-cap win test is conditionally gated (`if st.round_no > MAX_ROUNDS:`) and could pass vacuously; `_award_card`'s deterministic behavior and alliance-`kind`'s mechanical inertness are both unpinned.
- Shared infra: `test_viewer.py`'s two most relevant tests give false confidence — `_synthetic_events()` hand-authors the bystander record as `type: "message_meta"` (matching the delivered payload, not the real logged-record shape), and `test_seat_only_sees_entitled_observations`'s assertion is loosened by an arbitrary "+50" slack term large enough to swallow the leak; `test_metrics.py` has no test constructing an `observation` record of type `message`/`message_meta` at all; there is also no test file anywhere for `scripts/analyze_game_steering.py`, the sibling copy of the message-double-count bug that actually produces the published numbers.

## Verified-clean properties

- The "unbiased random legal moves" fallback claim **holds** in the shared runner code: `runner.py:151-159` computes `legal = game.legal_actions(state, active)` once before the parse-retry loop and draws `rng.choice(legal)` from the single seeded `random.Random(seed)` instance, uniformly and with no `legal[0]`/index bias, verified by direct code trace across all five game engines and by an empirical 1500-draw test (300 forced-fallback ONW matches, 5 vote targets each): distribution 19.4%-20.5% per target, uniform to within sampling noise, with target 0 (the index a bug would overweight) in fact the least-selected.
- **EXCEPT** two per-game legal-set completeness violations that make the pool sampled from non-representative, even though the sampling itself is uniform:
  - **Diplomacy** — the movement/build legal-action pool structurally excludes SUPPORT and CONVOY orders entirely (HOLD/MOVE/BUILD-Army only), so fallback (and RandomPlayer) can never produce a SUPPORT/CONVOY order regardless of true legality.
  - **Risk** — the `PH_FORTIFY` legal-action pool includes only the maximal-count fortify move per (src,dst) pair, excluding all partial-count fortifies that `parse_action` itself accepts.
- **Secret Hitler and Monopoly win attribution are correct**: SH `rewards()` maps role→team→1.0 iff team==winner_team, verified correct for both special win paths (Hitler-elected, kill-Hitler) by direct positive drive; Monopoly's money accounting (`_pay`, `_bankrupt`, rent doubling, GO salary, turn-cap richest-player identification) was traced and found correct, with the sole caveat being the undocumented tie-break order-bias noted above (not a correctness defect of the arithmetic itself).
- **ONW fallback verified uniform**: same shared `runner.py` mechanism as above, independently confirmed via the 300-match/1500-draw ONW-specific reproduction.

## Addendum (2026-07-22): v2 re-run provenance — leak impact corrected downward

The v2 re-runs (`data/runs/game_steering_v2/`, `data/runs/sh_steering_v2/`; fixed
engines, matched seeds, 125 matches each, 0 failures) produced decisive new
evidence that **revises two `affects_reported_numbers` judgments**:

- **The production match harness never rendered the leaked observations.**
  Production matches run inside the Modal worker with an in-worker player
  (`game_theory_llm/steering/modal_app.py::_LocalSteeredPlayer`), whose
  `receive_observation` renders only `message`/`message_meta`/`alliance_event`/
  `phase_change` and silently drops `action`-type obs. Both the ONW night-action
  leak and the SH per-vote broadcast carried payload type `action` — so neither
  ever entered a production decision prompt. The audits' delivery traces went
  through `players/llm.py` / `players/steered_llm.py`, which DO render
  `action` obs; those classes were not the ones used for the published runs.
- **Empirical proof:** SH v2, run on the demonstrably fixed engine (its logs
  contain the new `last_vote_tally` reveal), replays v1 **byte-identically** —
  125/125 matches with identical action sequences and identical free-text
  messages at temperature 0.7 (generation is deterministically seeded per
  (seed, seat, call)). Identical outputs under changed obs routing are only
  possible if prompts were unchanged, i.e. the leaks were decision-inert.
  ONW v2 diverges from v1 because the ONW engine itself evolved between the
  v1 run (2026-05-30) and now (e.g. `pass_talk`, mean turns 13 → 28), not
  because of the leak fix.
- **Revised judgments:** ONW night-action leak (Paper F1) and SH sequential
  ballot (Paper F2): `affects_reported_numbers` → **no at the decision level**;
  they remain real engine/obs-layer bugs (now fixed, with tests) that would
  contaminate any consumer rendering `action` obs (the library player classes,
  the viewer). The **whisper double-count remains the sole confirmed
  contamination channel** of published gameplay numbers (judge transcripts +
  message metrics), corrected in the v2 analysis.
- **New units finding (Critical, confirmed):** `analyze_game_steering.py`'s
  `n_fallback` (and the stats table's `fb` column) is a raw per-match event
  count, not a rate. True pooled fallback rates recomputed from raw logs:
  SH 6.2% of actions at baseline / 8.6% at α=−4; ONW 0.4–1.3% across
  conditions. Any prior prose quoting `fb` values as percentages (e.g. the
  v1 "7.7%") repeated this units error.
